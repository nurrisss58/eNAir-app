# eNAir — шпаргалка к защите

Ссылки в формате `файл:строка` — открывай и показывай прямо на экране.

---

## 1. Что за проект, в двух предложениях

Сайт авиакомпании eNAir: 21 страница (главная, направления, бронирование, тарифы, пассажиры, оплата, флот, лояльность, контакты), статика на Flask, база PostgreSQL на Neon, деплой на Render через GitHub.

**Три слоя:**
- **Фронтенд** — HTML + CSS (сверстано из Figma) + один общий `navigation.js`, который оживляет страницы.
- **Бэкенд** — `app.py` на Flask: отдаёт файлы и 8 API-методов.
- **База** — PostgreSQL в облаке Neon, таблицы `users`, `flights` и `bookings`.

```
Браузер ──HTML/CSS/JS──> Render (Flask + gunicorn) ──SQL──> Neon (PostgreSQL)
                                ▲
                          GitHub (main) — автодеплой
```

## 3. Вопросы преподавателя и ответы

### «Где у вас калькулятор, который всё это считает?»

Калькуляторов **два**, оба на клиенте, в `navigation.js`.

**1. Стоимость билета — `navigation.js:1280` (`currentPriceBreakdown`):**

```js
const base = Number(state.flight.price);          // цена рейса из базы, ₸
const passengers = state.adults;                   // число пассажиров
const surcharge = {Lite:0, Flex:70, Business:260, First:520}[state.fare]; // $ надбавка
const flights = base * passengers;
const fare    = surcharge * 490 * passengers;      // 490 — курс ₸ за $1
const taxes   = 96 * 490;                          // сборы $96
total = flights + fare + taxes;
```

Пересчёт и вывод на экран — `navigation.js:1293` (`refreshTotal`), форматирование ₸/$ — `navigation.js:303` (`formatPriceKzt`). Цены в разметке помечены `data-price-kzt`, поэтому переключатель валюты (KZT/USD) пересчитывает их без перезагрузки.

**2. Калькулятор миль — `navigation.js:1608` (`recalculate` внутри `loyaltyPage`):**

Считает расстояние по формуле гаверсинуса (радиус Земли 3958.8 миль, строка `navigation.js:1614`), затем начисляет бонусы:

```js
baseMiles  = расстояние
tierMiles  = baseMiles * {Silver:.10, Gold:.25, Platinum:.50, Diamond:.75}
cabinMiles = baseMiles * {Economy:0, Premium:.10, Business:.325, First:.50}
total      = baseMiles + tierMiles + cabinMiles
```

### «Какой код вызывает увеличение шрифта при наведении курсора?»

**Никакой — размер шрифта при наведении не меняется нигде.** Это правильный ответ, и его легко доказать: во всех CSS всего 4 правила `:hover`, и ни в одном нет `font-size`.

Что происходит на самом деле — карточка приподнимается и чуть темнеет:

| Эффект | Где |
|---|---|
| Кнопки и кликабельные блоки: `filter: brightness(.97)` + `translateY(-1px)` | `navigation.js:465` |
| Карточки: `translateY(-3px)` + тень | `navigation.js:472` |
| Кнопка выбора рейса: фон + подъём | `enair-booking.css:100` |
| Ссылка «Назад»: смена цвета | `enair-rewards-enrollment.css:8` |

Если преподаватель имел в виду эффект «текст как будто стал больше» — это оптический обман от подъёма элемента на 1–3 px и смены яркости, размер шрифта константный.

### «Где ваша база данных? Что за СУБД?»

PostgreSQL 16 в облаке **Neon**. Строка подключения лежит в переменной окружения `DATABASE_URL` на Render, в код не вписана.

```python
# app.py:52
def get_db():
    database_url = os.environ.get("DATABASE_URL")
    if database_url:
        return psycopg2.connect(database_url, sslmode="require", connect_timeout=10)
```

`sslmode="require"` — шифрованное соединение, `connect_timeout=10` — чтобы не зависнуть, если база «просыпается».

**Таблицы** (создаются в `app.py:124`):
- `users`: `id`, `name`, `email` (UNIQUE), `password`, `password_hash`, `created_at`;
- `flights`: `id`, `flight_number`, `departure_city`, `arrival_city`, `departure_time`, `arrival_time`, `price`, `seats_available`, `aircraft`, `seed_key` (ключ засева, чтобы деплой не дублировал рейсы);
- `bookings`: `id`, `reference` (номер брони, UNIQUE), `user_id`, `flight_id`, снимок рейса (`flight_number`, города, оба времени), `cabin`, `fare`, `passengers`, `passenger_names`, `total_price`, `card_last4`, `status`, `created_at`.

Цены в базе хранятся в долларах, а API пересчитывает их в тенге по курсу 490 (`_price_kzt`, `app.py:632`) — поэтому сумма одинаковая в карточках, тарифах и на оплате.

### «Покажите, откуда берутся рейсы»

`GET /api/flights` → `app.py:308`:

```sql
SELECT id, flight_number, departure_city, arrival_city,
       departure_time, arrival_time, price, seats_available, aircraft
FROM flights ORDER BY departure_time;
```

Ответ отдаётся JSON, фронтенд рисует карточки в `enair-booking.html` (функция `loadFlightsFromDB`), а страница поиска `booking-search.html` подставляет те же рейсы в свои карточки (`paintFlightRow`, `navigation.js:1201`) — поэтому на карточке видны настоящий номер, цена и остаток мест.

### «Как покупается билет и что происходит с местами?»

1. На странице оплаты кнопка Pay вызывает `completeBooking()` (`navigation.js:1488`).
2. Фронтенд отправляет `POST /api/book` с `flight_id`, числом пассажиров, тарифом и суммой.
3. Сервер в **одной транзакции**: блокирует строку рейса `SELECT ... FOR UPDATE`, проверяет остаток, вычитает места (`UPDATE flights SET seats_available = seats_available - N`), создаёт номер брони `EN######` и пишет строку в `bookings` (`app.py:452`).
4. Ответ содержит номер брони, снимок рейса и `seats_left` — сколько мест осталось после покупки.
5. Фронтенд показывает **чек** (`showReceipt`, `navigation.js:1390`): номер брони, пассажиры, маршрут, рейс, даты, тариф, разбивка цены, последние 4 цифры карты и остаток мест. Кнопка «Print / Save PDF» печатает только чек (правила `@media print` в `injectCSS`).
6. Если мест не хватает, сервер отвечает `409` и бронь не создаётся; на карточках рейса с нулём мест кнопка Select выключена и написано «Sold out».

**Почему `FOR UPDATE`:** без блокировки два одновременных заказа могли бы прочитать одинаковый остаток и продать одно и то же последнее место.

### «Как работает регистрация? Куда девается пароль?»

1. Форма в модальном окне — `navigation.js:560` (`openAuthModal`), отправка — внутри неё же (`form.addEventListener('submit', ...)`).
2. `POST /api/register` — `app.py:339`.
3. Пароль **не хранится в открытом виде**: `generate_password_hash(password)` (werkzeug, стойкий хеш с солью), в базу уходит только `password_hash`.
4. Вход: `check_password_hash(...)` — `app.py:381` (внутри `login`), сравнение с хешем.
5. Все SQL-запросы параметризованные (`%s`), поэтому SQL-инъекция невозможна.

### «Как защищён сайт?»

- Пароли — только в виде хешей.
- SQL — параметризованные запросы, без склейки строк.
- Файлы: раньше Flask отдавал по прямой ссылке `app.py` вместе с паролями — теперь включён белый список расширений (`app.py:19`, `app.py:26`), и `/app.py`, `/Procfile`, `requirements.txt` возвращают 404.
- Секреты — в переменных окружения Render, не в репозитории.

### «Где логика навигации/кнопок?»

`navigation.js`:
- карта маршрутов — строки 28–41 (`routes`);
- `clickable()` (`:450`) — делает любой элемент кликабельным, добавляет `role="button"` и обработку Enter/Space (доступность);
- `globalNav()` (`:785`) — меню и подвал;
- `mobileMenu()` (`:1718`) — меню на телефоне.

### «Как хранится состояние бронирования?»

В браузере, `localStorage`, ключ `enairState` (`navigation.js:291`, сохранение — `:298`): маршрут, даты, пассажиры, тариф, выбранный рейс и имена пассажиров для чека. Сессия пользователя — `enairUser` (`:323`), валюта — `site_currency`. Поэтому выбор не теряется при переходе между страницами. Сама бронь живёт в базе (`bookings`), а не в браузере.

### «Как сайт ведёт себя на телефоне?»

Страницы свёрстаны из Figma с фиксированными размерами, поэтому адаптив вынесен в **один файл `responsive.css`** — он подключается из `navigation.js` (`injectResponsive`) и работает только при ширине до 900 px. Внутри точечные правки: секции с отступами 80 px переходят на 20 px, заголовки с `white-space:nowrap` начинают переноситься, строки карточек становятся колонками, фиксированные высоты снимаются. На десктопе файл ничего не меняет.

Почему так, а не правкой 21 страницы: страницы — экспорт из Figma, классы вида `frame-56` уникальны для каждой, и правки в общем файле проще поддерживать.

### «Где карта и как она работает?»

Интерактивная карта на **Leaflet**. Библиотека подключается с CDN, ключ не нужен, тайлы — OpenStreetMap.

- `navigation.js:164` — `networkMap()`: создаёт карту, ставит маркеры хабов, рисует дуги маршрутов;
- `navigation.js:117` — `loadLeaflet()`: загрузка библиотеки;
- `navigation.js:151` — `routeCurve()`: кривая между городами, чтобы линии не резали карту по прямой;
- координаты — объект `mapLocations` (`navigation.js:46`);
- по клику на город вызывается `flyTo()` — карта плавно перелетает, а `drawNetwork()` перерисовывает маршруты;
- **подстраховка:** карта из макета (изображение мира с городами) остаётся под интерактивной и видна, пока Leaflet и тайлы не загрузились. Поэтому блок никогда не выглядит пустым.

**Про надёжность загрузки (частый вопрос «почему карта не появилась сразу»):** библиотека грузится не с одного CDN, а по очереди с трёх (unpkg → jsDelivr → cdnjs), у каждой попытки таймаут 6 секунд. Интерактивный слой проявляется только после первого загруженного тайла, а размер контейнера пересчитывается в `invalidateSize()` на `load`, `resize`, `pageshow`, смене вкладки и через `ResizeObserver`. Если ни один CDN не ответил, остаётся карта из макета, а чипы городов продолжают работать — выбирают пункт назначения.

**Что ответить про «почему без ключа»:** «OSM-тайлы бесплатны и не требуют регистрации, поэтому карта не зависит от платного сервиса и не сломается на защите».

### «Почему сайт обновляется сам после пуша?»

GitHub → Render: сервис типа **Web Service**, автодеплой с ветки `main`, запуск через `gunicorn app:app` (файл `Procfile`), зависимости — `requirements.txt`. Пуш в `main` = новая сборка и перезапуск.

## 6. ИИ-ассистент: как работает и что отвечать

Виджет в правом нижнем углу — `assistant.js` (подключается из `navigation.js`, поэтому лежит на всех страницах).

**Схема ответа:**

```
Кнопка «Спросить ассистента» → POST /api/assistant {message}
        │
        ├─ есть AI_API_KEY? → запрос к языковой модели (app.py: _ask_ai)
        │        └─ ошибка/таймаут → откат на правила
        └─ нет ключа → движок правил (app.py: _rule_reply)
                 └─ читает рейсы из Neon (_flights_snapshot)
```

**Что говорить преподавателю:**

- «Ассистент работает в двух режимах: по умолчанию — движок правил плюс реальные данные из базы, а если на сервере задан ключ, отвечает языковая модель. Сайт не зависит от внешнего API: если ключа нет или сервис недоступен, ответ всё равно будет».
- «Ассистент не выдумывает рейсы: список городов, дат и цен он берёт запросом `SELECT` из таблицы `flights` — это видно в функции `_flights_snapshot`, `app.py`».
- «Ключ хранится в переменных окружения Render, в репозитории его нет».
- «Ответ приходит JSON-ом `{reply, source, suggestions}`, где `source` — `rules` или `ai`. На экране видно, что это демо».

**Что спросят про «настоящий ли это ИИ»:**

Честный ответ: «Базовый режим — экспертные правила и поиск по ключевым словам, это объяснимо и предсказуемо. Режим модели включается одной переменной окружения, и тогда ответы генерирует LLM с доступом к расписанию из базы».

**Файлы:**

| Что | Где |
|---|---|
| Виджет (UI, чат, запросы) | `assistant.js` |
| Эндпоинт | `app.py:907` — `assistant()` |
| Движок правил | `app.py:701` — `_rule_reply()` |
| Данные из базы для ответов | `app.py:641` — `_flights_snapshot()` |
| Режим языковой модели | `app.py:894` — `_ask_ai()` |
| Включение режима ИИ | переменная `AI_API_KEY` на Render (+ `AI_MODEL`, `AI_BASE_URL`) |

**Проверка на защите:** открыть виджет → «сколько стоит билет до Лондона?» → в ответе реальные рейс, дата и цена из базы.

**Как включить режим языковой модели:**

1. Получить ключ:
   - **DeepSeek** — `platform.deepseek.com` → пополнить баланс (от $2) → API keys → Create. Модель `deepseek-chat`, адрес `https://api.deepseek.com/v1`.
   - **Groq** (бесплатный тариф, быстрый) — `console.groq.com` → API Keys. Модель `llama-3.3-70b-versatile`, адрес `https://api.groq.com/openai/v1`.
   - **OpenRouter** — `openrouter.ai/keys`, есть бесплатные модели с суффиксом `:free`, адрес `https://openrouter.ai/api/v1`.
2. Render → сервис → **Environment** → добавить:
   - `AI_API_KEY` = ключ;
   - `AI_BASE_URL` = адрес из списка выше;
   - `AI_MODEL` = название модели.
3. Save → сервис перезапустится. В ответах `source` станет `ai`.

Ключ в репозиторий не попадает: он живёт только в переменных окружения Render.

**Роадмап:** `User Personas` — страница исследования, ссылка на неё добавлена в подвал в колонку `Company`.

## 7. Быстрые факты, если спросят «а это точно ваше?»

- 21 HTML-страница, 15 CSS, два общих JS (`navigation.js`, `assistant.js`) — свой код, без фреймворков.
- База — 3 таблицы (`users`, `flights`, `bookings`), 8 эндпоинтов API (включая `/api/book`, `/api/bookings/<reference>`, `/api/assistant` и `/healthz`).
- В расписании 16 демо-рейсов; повторный деплой не создаёт копий — у каждого рейса свой `seed_key`.
- Всё работает без сборки: чистые HTML/CSS/JS + Flask.
- Один и тот же код и на ноутбуке, и на Render — отличается только `DATABASE_URL`.
